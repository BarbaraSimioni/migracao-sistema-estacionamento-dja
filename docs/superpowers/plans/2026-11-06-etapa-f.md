# Etapa F Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrar as funcionalidades de `origin/dev` com migration, CORS, testes finais e correções de consistência, deixando a etapa F pronta para validação antes do merge em `main`.

**Architecture:** Criar uma worktree limpa a partir de `origin/dev`, reaplicar apenas os artefatos válidos da etapa F e testar as APIs Django pelo cliente de testes. O serviço de permanência permanece responsável pela transação e as views convertem validações e exceções em HTTP.

**Tech Stack:** Python 3.11, Django 5.2, SQLite, Django TestCase, Docker Compose, Nginx.

**Spec:** `docs/superpowers/specs/2026-11-06-etapa-f-design.md`

## Global Constraints

- Preservar integralmente a árvore de trabalho original até a validação da worktree.
- Aceitar rotas com e sem barra final.
- Manter SQLite no volume `/app/data`.
- Usar `Decimal` para valores monetários e ISO 8601 nas respostas.
- Não fazer merge em `main`.

## Review Focus

- IDs não numéricos em entrada devem retornar 400, não 500; coberto na Task 3.
- Atualização de vaga ocupada sem `status` deve manter `OCUPADA`; coberto na Task 3.
- Duas entradas concorrentes/lógicas para o mesmo veículo ou vaga devem resultar em conflito; coberto na Task 4.
- Exclusão de veículo ou vaga com permanência deve retornar 409; coberto na Task 4.
- Migration reversível deve remover somente as 15 vagas sem permanências; coberto na Task 1.
